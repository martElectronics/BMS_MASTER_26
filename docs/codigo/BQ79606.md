# `BQ79606` — Driver del monitor de celdas

`lib/BQ79606/BQ79606.h` · `.cpp`

## Propósito
Driver del **TI BQ79606A-Q1**, el IC que mide hasta 6 celdas + 6 NTCs y se encadena
en **daisy-chain UART** (protocolo propietario de TI). El driver abstrae toda esa
complejidad: autoaddressing, lectura de V/T, fallos y balanceo. Es **portable**
(ESP32/STM32) vía la struct `BQConfig` — la clase no se toca al portar.

## Conceptos clave
- **Cadena de ICs:** `TOTALBOARDS` ICs. **2 boards = 1 módulo**. Board par = 6 celdas,
  board impar = 5 (la celda 6 mide ~0 V). `CELLS_FOR_BOARD(b)` lo resuelve.
- **`TOTALBOARDS` (en el .h)** debe coincidir **EXACTO** con el HW. Cambiarlo exige
  recompilar+reflashear. Es la causa nº1 de "la cadena no responde".
- **Conversión:** raw ADC (complemento a 2) × 190.73 µV = voltios. Los NTC pasan por
  `_voltToTemp()` (curva del PCB). Lecturas de NTC fuera de rango / 0x8000 → "NTC abierto".

## API que usarás (desde `main.cpp`)
| Llamada | Qué hace |
|---|---|
| `begin()` | Pines + UART + **autoaddressing** + config de ADC/protecciones. `true` si OK. |
| `reInit()` | Re-inicializa en runtime (recuperación de comms). **Bloquea** unos s. |
| `readVoltages()` | Lee las 6 V de cada IC. Devuelve `BQResult` (OK/COMM_ERROR/CRC_ERROR). |
| `readTemperatures()` | Lee los NTCs → °C. Mismo `BQResult`. |
| `getMinVoltage()/getMaxVoltage()/getVoltageDelta()` | estadísticas de celda |
| `getMinTemp()/getMaxTemp()/hasOpenNtc()` | estadísticas térmicas |
| `getFaultStatus(board, fs)` | lee registros de fallo de un IC (`BQFaultStatus`) |
| `setBmsOk(bool)` | escribe el pin BMS_OK (HIGH=OK) — solo en cambios |
| `isOK()` | `true` si el autoaddressing está hecho |

## `BQResult` (importante para el main)
`OK` · `COMM_ERROR` (timeout/sin respuesta → conector/alimentación) · `CRC_ERROR`
(trama corrupta → ruido/EMI). El `main` cuenta ambos por separado: esa distinción es
**clave para diagnosticar** problemas de comunicación.

## Balanceo (no usado aún en `main`, pero implementado)
`startBalancing(board, cellMask, timer)` activa el balanceo **hardware** del IC.
La seguridad anti-cortocircuito la garantiza `CB_CONFIG = 0xDC` (alterna odd/even).
⚠ **NUNCA** usar `CB_SW_EN` directamente (activaría FETs adyacentes → corto). Y los
voltajes durante el balanceo **no son OCV fiable** (`isVoltageReadingReliable()`=false):
hay que esperar ≥5 s con FETs apagados antes de usarlos para SOC/timers.

## Gotcha de portabilidad (STM32) — leer si tocas pines
En STM32duino los tokens `PB_7`/`PC_5` son del enum **`PinName`**, NO índices Arduino.
Pasarlos crudos a `pinMode/digitalWrite` acciona **el pin equivocado en silencio**.
El driver usa `BQPin`/`BQ_DPIN()` para resolverlo. Si cableas un pin nuevo del BQ,
respeta ese mecanismo.

## Config (`BQConfig` en `main.cpp`)
`pinWake`, `pinFault`, `pinBmsOk`, `pinRx`, `pinTx`, `pinTxEnable` (-1 si no hay level
shifter — la PCB nueva no lo lleva), `baudrate` (125000).
